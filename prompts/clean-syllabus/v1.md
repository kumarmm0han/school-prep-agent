# Syllabus clean pass — prompt v1

You are cleaning the **syllabus (topic) list** of a single textbook chapter.
The input is OCR-derived markdown, so it may be damaged: glued words, broken
characters (`Rajyα Sabha`, `Parliameņtary`), embedded sub-headings that split
one list, list markers, page numbers, and exam-instruction brackets.

You will be given two things:

1. **SOURCE** — the chapter's head area, verbatim (this is the only text your
   output may be grounded in),
2. **CAPTURED** — a machine-captured item list (JSON array). It may be empty,
   partial, or corrupted. Treat it as a hint about what was found, not as the
   answer.

Return **only** the cleaned topic list as a **raw JSON array of strings** —
no markdown fences, no keys, no prose, no trailing commas.

## Rules

1. Each array element is ONE short topic phrase — a noun phrase, not a
   sentence, not a paragraph.
2. Keep the source's order of topics.
3. Split a line that actually holds two or more distinct topics into separate
     items; merge fragments of a single topic that OCR split across lines.
4. Drop non-topic lines: page numbers, running headers/footers, image or
   figure descriptions, and exam/test-policy annotations (including text in
   `[brackets]` about what "will be tested").
5. Strip list markers, numbering, and enumeration prefixes (`-`, `1.`, `(i)`,
   `(a)`, `ii)`...) from each item.
6. Do NOT rename, paraphrase, summarize, translate, or add topics. Fixing an
   obvious OCR character glitch (e.g. `Rajyα` → `Rajya`) is allowed only when
   the fix is unambiguous from surrounding source text. Every topic you
   return must be present in the SOURCE — topics not grounded in the source
   are rejected by a deterministic validator and the whole list is discarded.
7. The list length must stay within 50% to 3× of the CAPTURED item count (the
   validator enforces this); if CAPTURED is empty, return between 1 and 15
   items grounded in the SOURCE.
8. If the source contains list-like syllabus lines (numbered items, `(i)`/
   `(ii)` items, dash lines — even when split by embedded sub-headings), the
   output MUST be built from those topic lines. A title-only answer is
   WRONG whenever such lines exist. Embedded sub-headings that merely
   enumerate (e.g. `#### 1. The Union Legislature`) are list separators, not
   the only content: recover the topic lines under them.
9. If the SOURCE contains no recoverable topic list, return `[]`. Do NOT
   invent topics to avoid that: an empty answer is quarantined by the
   validator (never applied), the chapter is flagged for a human — that is
   the correct failure mode.

Output nothing but the JSON array.
